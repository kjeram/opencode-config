# Engineering Commands

Explicit command entry points for engineering workflows. These commands generally load the corresponding skill to perform the work.

- **[ask](./ask.md)** — Route a situation to the right engineering workflow.
- **[code-review](./code-review.md)** — Review changes against repository standards and their originating spec.
- **[grill-with-docs](./grill-with-docs.md)** — Interview through a plan or design and record agreed terminology and decisions.
- **[implement](./implement.md)** — Implement work from a spec or ticket.
- **[implement-spec](./implement-spec.md)** — Implement a complete spec by coordinating its ticket graph.
- **[improve-codebase-architecture](./improve-codebase-architecture.md)** — Find and discuss codebase deepening opportunities.
- **[retro](./retro.md)** — Retrospect on a coding session and propose environment improvements.
- **[setup-skills](./setup-skills.md)** — Configure this repository for the engineering workflows.
- **[to-spec](./to-spec.md)** — Turn the current conversation into an issue-tracker spec.
- **[to-tickets](./to-tickets.md)** — Break a plan or spec into dependency-linked tickets.
- **[triage](./triage.md)** — Triage an issue or external pull request.
- **[wait-what](./wait-what.md)** — Re-explain a message that did not land. This command uses the productivity `wait-what` skill.
- **[wayfinder](./wayfinder.md)** — Map and resolve decisions for a large multi-session effort.
